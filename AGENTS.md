# AGENTS.md — Project Memory

## Context
Diabetes chatbot: FastAPI backend (`backend/`), React frontend (`frontend/`), docker-compose deployment.
Security hardening of the backend auth/rate-limiting/DB was implemented on `main` (see `git log` around 956f335..HEAD).
The original external security report PDF (`relatorio_chatbot_insulinoterapia.pdf`) is no longer present on disk; these notes are the reconstructed + code-verified record.

## Security issues — all resolved as of HEAD

All issues from the original security report have been fixed. Residual notes:
- The **semantic cache** (`init_semantic_cache`, `RedisSemanticCache` via `set_llm_cache`) is GLOBAL — keyed by LLM prompt hash, not user — so it could serve one user's PII to another. It is now **disabled by default** (`SEMANTIC_CACHE_ENABLED=false`, fail-closed) and only initialized when explicitly opted in. The per-user PII store (conversation message cache) IS invalidated on delete.
- The **LangGraph checkpointer** (`create_postgres_checkpointer`, `CHECKPOINTER_ENABLED`) stores thread state in Postgres keyed by `user_{user_id}`; it is NOT covered by the user FK cascade. `purge_user_checkpoint_threads` (in `db_client.py`, called from `ConversationService.purge_user_data` on `DELETE /auth/me`) now deletes the `checkpoints`/`checkpoint_blobs`/`checkpoint_writes` rows for the thread. Disabled by default.

## Solved (for reference)
- Real client IP via **trusted-proxy resolution** + Redis-backed slowapi limiter (`api.py`, `_client_ip`): forwarded headers (`X-Real-IP`, `X-Forwarded-For`) are honored ONLY when the request's direct peer is in `TRUSTED_PROXY_IPS` (comma-separated IPs/CIDRs, `config/security.py`; compose default `172.16.0.0/12`); otherwise the peer address is used. The ui nginx **overwrites** both headers with `$remote_addr` (`ui.conf.tmpl`) so a client cannot spoof its IP through the proxy. The starlette TestClient peer is the literal string `testclient` — `test_api_endpoints.py` sets `TRUSTED_PROXY_IPS=testclient` so its per-IP `X-Forwarded-For` isolation still works.
- Uniform generic 401 on login (no 423/429 enumeration); lockout keyed on (username, IP).
- Fail-closed Redis behavior (rate limit, lockout, query throttle, token blacklist).
- Per-user `/query` rate limit (default 30/min, `QUERY_RATE_LIMIT`/`QUERY_RATE_WINDOW_SECONDS`).
- Strong JWT secret enforced at startup (no DEV bypass).
- Input caps: `QueryRequest.query <= 2000`, `session_id <= 64`, `username <= 64`, `password <= 128`.
- DB hardening: compose postgres/backend ports no longer published; required `POSTGRES_DB/USER/PASSWORD`, `DATABASE_URL`, `JWT_SECRET_KEY` (no `chatbot` defaults).
- **JWT moved out of localStorage into an httpOnly cookie** — `frontend/src/lib/auth.ts` deleted; `api.py` sets `access_token` cookie (`HttpOnly`, `Secure`, `SameSite=lax`, `max_age` = JWT expiry) on login, reads cookie-or-Bearer in `get_current_user` (`_request_token`), clears it on logout/delete. `frontend/src/lib/api.ts` uses `credentials: 'include'` and no Authorization header; logout calls POST `/auth/logout`. Config: `AUTH_COOKIE_*` in `config/security.py` (`AUTH_COOKIE_SECURE=false` only for plain-HTTP dev). CSRF is mitigated by SameSite=Lax + CORS origin allowlist. Bearer still works for API clients/tests.
- **UI served over TLS with security headers** — `dockerfile.ui` nginx now: HTTP :80 → 301 → HTTPS :443; self-signed cert generated at container start by `/docker-entrypoint.d/10-security-config.sh` (renders `/etc/nginx/ui.conf.tmpl` via envsubst); real certs mountable at `/etc/nginx/certs/server.{crt,key}` (enables HSTS; HSTS stays OFF for self-signed to avoid browser lockout). Headers: CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`. Compose: `UI_HTTP_PORT` (default 3000→80), `UI_HTTPS_PORT` (default 443→443), `./certs` volume (gitignored).
- **API docs disabled by default** — `/docs`, `/redoc`, `/openapi.json` only served when `DOCS_ENABLED=true` (opt-in for dev); `DOCS_ENABLED` in `config/infrastructure.py` via `get_bool`, read in `api.py` `FastAPI(...)` kwargs and the root endpoint.
- **`DELETE /auth/me` purges cached user data** — endpoint calls `chatbot.purge_user_data(user_id)` (→ `ConversationService.purge_user_data` → `MessagesRepository.invalidate_cache(conversation_id)`, removes the `chat:conv:{id}:messages` Redis key) BEFORE `auth_service.delete_user` deletes the DB row, so cached PII cannot outlive the account.
- **CORS scoped** — `api.py` CORSMiddleware: `allow_methods=["GET","POST","DELETE","OPTIONS"]`, `allow_headers=["Content-Type","Authorization"]` (no `*`), origins still from `FRONTEND_ORIGINS` allowlist.
- **No password in process args** — `scripts/bootstrap_user.py` reads `BOOTSTRAP_PASSWORD` env var or interactive `getpass` (no `--password` CLI flag; `--password` now errors as unrecognized). `dockerfile.backend` seeds `BOOTSTRAP_USERS` (`user:pass,...`) by exporting each password via `BOOTSTRAP_PASSWORD` to `bootstrap_user --username`, never on the CLI. Bootstrap passwords must be >= 8 chars with letters AND digits.

## Security work on this branch (M4/M5/M6, after 956f335..HEAD)
- **M4 — container runs as non-root, multi-stage build** — `dockerfile.backend` is now two-stage: a `builder` stage (build-essential/git) collects all wheels with `pip wheel`; the slim runtime stage installs only runtime system libs (`--no-install-recommends`), installs wheels offline (`pip install --no-cache-dir --no-index --find-links=/wheels`), then deletes `/wheels` and the pip cache. Process runs as `appuser` (`USER appuser`, uid/gid via `--build-arg APP_UID/APP_GID`, default 1000). IMPORTANT: the `./data/processed` host mount must be writable by that uid — on this host the user is uid 1000, so it matches; for other hosts pass `--build-arg APP_UID=$(id -u)` (or chown the dir). `.dockerignore` also excludes `certs/` and `backend/test/`.
- **M5 — pinned, audited dependencies** — every package in `backend/requirements.txt` is pinned, including transitive pins that clear known CVEs (starlette 1.3.1, PyJWT 2.13.0, pypdf 6.14.2, aiohttp 3.14.1, cryptography 48.0.1, idna 3.15, mako 1.3.12, pillow 12.3.0, pyasn1 0.6.4, pydantic-settings 2.14.2, python-multipart 0.0.31, setuptools 83.0.0, urllib3 2.7.0, json-repair 0.60.1, langchain-core 1.3.3, langchain-classic 1.0.7, langgraph-checkpoint 4.1.1, langgraph-sdk 0.3.15, langsmith 0.8.18). The dev `.venv` was upgraded to match. `pip-audit` residual on `requirements.txt`: `ecdsa 0.19.2` (no fix published yet) and `lightrag-hku 1.4.15` (fixed in 1.5.4 — upgrade DEFERRED: RAG API is used directly and the ingest pipeline must be re-tested first). Run `scripts/audit_dependencies.sh` (installs pip-audit into the venv if missing) or `backend/.venv/bin/python -m pip_audit -r backend/requirements.txt`. No `.github/workflows` exists yet; the audit script is ready to wire into CI. NOTE: the `.venv` is a PARTIAL install — torch/transformers/unstructured/langchain-unstructured are in requirements.txt but NOT installed locally (they're only needed for the ingest/kb_builder path, which tests mock out).
- **M6 — untrusted-data guards against prompt injection** — `backend/src/config/prompts.py` defines `UNTRUSTED_DATA_GUARD` and wraps every untrusted interpolation in `<input_inicio>/<input_fim>` delimiters labeled as DATA, never instructions: RAG context in `SYSTEM_PROMPT`, user query via the new `USER_QUERY_PROMPT`, plus the critique/refinement/summary inputs. `query_processor.py` `_node_generate_initial` now sends `USER_QUERY_PROMPT.format(query=...)` instead of the raw query. `SYSTEM_PROMPT` still has the single `{context}` placeholder, so `.format(context=...)` callers are unchanged.

## LOW items resolved (after M4/M5/M6)
- **L1 — no internal details in responses** — `_raise_api_error` (`api.py`) now logs the exception detail (`logger.error`) and always returns the generic user-safe message; RAG client returns a generic `"RAG query failed"` dict (the real exception stays in logs only) instead of `str(e)`.
- **L2 — `__Host-` cookie, password re-confirmation, secret strength, fingerprinting** — `get_auth_cookie_name()` (`config/security.py`) auto-prefixes the cookie with `__Host-` when Secure + Path=/ + no Domain; `DELETE /auth/me` now requires a JSON body `{"password": ...}` (schema `AccountDeleteRequest`, verified via `AuthenticationService.confirm_password` with dummy-hash timing equalization; 403 on mismatch) and the frontend prompts for the password (`ChatPage`/`App`/`api.ts`); `_validate_jwt_secret` warns (non-fatal) when the secret is < 64 chars; `/` no longer discloses the version. `/health` stays unauthenticated on purpose (container healthcheck probes it without auth). HSTS remains nginx-level only (correct: nginx is the TLS terminator; enabled automatically when real certs are mounted).
- **L3 — dead config + stale probes** — startup warns (non-fatal) when `AUTH_ENABLED` is set (it is unused; auth is always enforced). `scripts/check_stack_health.sh` no longer probes the removed `qdrant`/`neo4j` services.
- **L4 — postgres starts with only DATABASE_URL** — `docker-compose.yml` no longer `:?`-requires `POSTGRES_DB/USER/PASSWORD`; the new `scripts/postgres-entrypoint.sh` (mounted into the postgres container) derives them from `DATABASE_URL` (percent-decoding handled, verified against `postgres:16-alpine`), with explicit `POSTGRES_*` env vars taking precedence. `POSTGRES_*` must be percent-encoded in `DATABASE_URL` if they contain URL-special characters (`@`, `:`, `/`, ...).
- Note: the deployed `.env` `JWT_SECRET_KEY` is 42 chars (startup warning fires; ok) and `AUTH_ENABLED=true` (ignored; warning fires). Neither is fatal.
